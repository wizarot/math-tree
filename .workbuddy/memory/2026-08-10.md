## galaxy.html 性能修复（卡顿 → 流畅）
- 问题根因：原实现每帧对 702 个节点都做 `shadowBlur`（符号三层霓虹 + 已点亮圆盘光晕 + 稀有度外环），`shadowBlur` 是 Canvas 最贵操作，导致页面卡到爆。
- 修复方案：**把发光预烘焙进离屏 sprite，运行时只做廉价 `drawImage`**。
  - 新增 3 张共享「霓虹光球」径向渐变 sprite（`bakeGlowDisk`，gold/cyan/gray，128px，全节点共用，内存极小）。
  - 符号渲染改为：lighter 叠光球（随 breath 缩放+调透明做呼吸）+ 核心符号 + 白色管芯，零实时模糊。
  - 已点亮圆盘去掉 `shadowBlur`（光晕改由符号霓虹承担）；稀有度外环改用 `lighter` 双层描边模拟辉光，去掉 `shadowBlur`。
  - 仅保留 `shadowBlur` 在选中/悬停圆盘（1~2 节点）和邻居边（少量），开销可忽略。
- 结论：批量节点的实时 `shadowBlur` 全部移除，每帧仅约 3000+ 次廉价 drawImage，无实时模糊。
- 复用价值：这是 Canvas 大量发光节点的通用性能模式（烘焙 glow sprite 代替 per-frame shadowBlur），值得沉淀为 skill。
- **用户已验证**：在本地 `python -m http.server` 起的 `http://127.0.0.1:8000/galaxy.html` 上确认效果满意、基本不卡顿，优化方案有效。

## 连线渲染优化（去掉批量虚线动画）
- 用户反馈：开启「显示全部连线」后，几百条边的每帧虚线流动 `setLineDash` + `lineDashOffset` 偏移计算太占渲染资源；且亮线颗粒太长。
- 重构方案：
  - **仅选中节点的邻居边**（`highlightEdges`，焦点模式）保留流动虚线，亮颗粒缩短为 `[3,14]`（原 `[5,12]`，亮段更短、间隙更长 → 颗粒更小），保留青色辉光（仅少数几条，开销可忽略）。
  - **已掌握/可解锁/显示全部连线** 全部改为**实心静线**（去掉虚线和动画），与最初版本一致，零 `setLineDash` 偏移计算。
  - `showFlow` 开关继续仅控制选中邻居边的流动（「虚线流动」勾选框仍有效）。
- 结果：`setLineDash` 每帧仅出现在选中邻居边（数百条边的静态实心 `stroke` 无虚线开销），动画偏移计算从「全量边」降到「仅选中节点的几条」。
- 语法校验通过（37037 字符）。

## 首屏初始视图改为放大中心
- 用户需求：加载后首屏直接看到放大的星系中心核心，充满屏幕（而非适配全图的小图）。
- 新增 `initialZoom()`：在 `fitScreen()` 的适配全图缩放基础上乘 `INITIAL_ZOOM`（初值 2.8，后用户改为 18），并把世界原点（星系中心）居中到屏幕中心。
- `init()` 中 `fitScreen()` → `initialZoom()`（加载即放大中心）。
- resize 监听改为 `preserveViewOnResize()`：保持当前视图中心世界坐标不变，仅同步画布尺寸，避免窗口缩放时跳回适配全图（旧的 `fitScreen()` 在 resize 中会重置缩放）。
- 确认滚轮缩放范围 `0.05~20`，用户可随时滚出回全景，不会卡在放大态。
- 语法校验通过（37597 字符）。

## index.ordered.html 滚轮缩放修复（以鼠标为中心）
- 问题：`stage` 的 wheel 缩放虽声称以光标为中心，但平移公式写错：`view.tx=wpt.x-(wpt.x-view.tx)*(ns/view.s)` 会让光标下的世界点随缩放漂移（验证：s=1,tx=100,wpt=50 时缩放后屏幕位置从 150 漂到 162）。
- 修复：改为标准光标居中公式 `view.tx=view.tx+wpt.x*(view.s-ns)`（ty 同理），保持光标下的世界点屏幕位置不变。
- 仅修改 wheel handler 内两行平移计算，缩放系数/范围（0.15~4）、`clientToWorld`、`applyView` 均未动。

## index.ordered.html 节点图标更换为 galaxy 同款（mtf-sprite.svg 专属符号）
- 需求：把 ordered 页节点图标换成和 galaxy.html 一样的。
- 关键事实澄清：`assets/mtf-sprite.svg` 含 **503 个 `mt_xxx` + 199 个 `cn_xxx` = 702 个 `<symbol>`**（之前被 grep head_limit 误导以为只有 cn_）。galaxy 用 `symCache.get(t.id)`（t.id 即 `mt_xxx`）取专属符号——所以 galaxy 符号一直正常显示，只对 503 个 mt_ 节点有符号，其余 199 个在 galaxy 里也是无符号。
- 实现：`loadSprite()` 异步 fetch+解析 mtf-sprite.svg，按 id 存入全局 `SPRITE`；`load()` 里 render 前 `await loadSprite()`；节点 sigil 构建改为优先 `SPRITE[t.id]`（importNode 克隆 symbol 子节点，设 `color:#fff` 让 currentColor 取白、non-scaling-stroke + stroke-width=1.8 保持清晰，64 体系按 symScale=(R/13)*0.375 适配显示尺寸），未命中则回退原领域 sigil。
- 匹配率 503/702=71.7%，覆盖 galaxy 实际有符号的全部节点；其余 199 个回退领域 sigil（比 galaxy 还多一层标识，不冲突）。
- 语法校验通过（主 <script> 28667 字符）。列头/详情面板的领域 sigil 未改动（保留领域标识）。
